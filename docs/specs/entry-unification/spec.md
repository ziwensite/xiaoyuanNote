# 统一条目：事件即任务、任务即事件

状态：设计稿，决策已定（2026-11-10），实施中。本轮先落 P0（`⏰` 一等 token）。

## 0. 结论

1. **一条条目只有一份权威数据：那一行任务文本。** 日历与笔记不是两份数据，而是同一行的两个渲染器。日历侧显示区间/地点/参与人，笔记侧显示优先级/依赖/完成时间，共用字段只存在行里。
2. **轻量条目没有第二个文件。** 它就是某个周期笔记里的一行，日历通过现有的 `buildCalendarIndex`（已把任意笔记里带 `📅` 的任务按天入桶）直接渲染，零新增存储、零同步。
3. **重量条目（要纪要/地点/参与人/时刻区间）也把那一行留在创建日日记**；事件笔记放在现有 `Calendar/` 下，**只存事件专属 extras 与 `entry_uid` 指针**，不存共用字段的第二个副本。日历按 uid 跨文件 join 出"行 + extras"（D1 = B）。
4. **所有行级改写仍只走 `writeTaskLine`**；在它外面加一层薄薄的 `writeEntry`，负责"挑目标文件、定位插入点、幂等去重、原子写、与投影合并成一次事务"。字节级的规范化规则不变。
5. **周期笔记扩到五类**（日/周/月/季/年），沿用参考实现的"每类三个配置项（文件夹、命名格式、模板）+ 周期锚点 + 打开即建"结构；现有日记的三个设置原样迁移，不破坏已有文件。
6. **参考实现没有"自动捕获"，也没有任何周期笔记之间的汇总。** 它的捕获全是手动触发（命令/头部按钮），自动化只有"自动补 `➕`/`📅`"和"文件不存在则按模板创建"。所以本设计把"自动"落在**事件创建这一动作**上，并要求写入幂等；周报/月报之间的汇总需单独拍板（见 §9 D4）。
7. **`⏰` 原本不是任务行模型的一部分**，走一遍 `writeTaskLine` 会被挤到行尾（`✅` 之后）。D3 已决定把它提升为一等 token 并固定在 `📅` 之后——这一条已在 P0 落地，是后续所有统一条目工作的前提。
8. **旧 `Calendar/` 笔记不批量改写。** 没有正文任务行的旧笔记继续以 frontmatter 为准、只读渲染，新旧共存；只有用户主动编辑某一条时才可能升级它。

## 1. 术语与模型

- **条目（entry）**：用户眼里的一件事。日历里叫事件，笔记里叫任务。
- **行（line）**：`- [ ] 写周报 #work 📅 2026-11-12 ⏫`。唯一权威载体。
- **轻量条目**：只需要共用字段 + 任务专属字段。没有独立文件。
- **重量条目**：需要事件专属字段（时刻区间、地点、参与人、纪要）。有独立事件笔记。
- **投影（projection）**：由行推导出的只读视图。日历里的一个事件、事件笔记的 frontmatter，都是投影。

```
                  ┌──────────── 一行任务文本（唯一权威） ────────────┐
                  │  - [ ] 写周报 #work 📅 2026-11-12 ⏫ 🆔 t001     │
                  └───────────────┬───────────────────┬─────────────┘
                                  │                   │
                    轻量：留在周期笔记          重量：行也留在周期笔记
                                  │                   │
                     日历按 📅 入桶（现有逻辑）   事件笔记只存 extras + uid 指针
                                                 日历按 uid 跨文件 join
```

D1 = B 的直接后果：**共用字段在任何时候都只有一份**，就在那一行里；事件笔记不再承载 `summary`/`dtstart` 的第二份权威副本。它自己的 frontmatter 只描述事件专属的部分（时刻、地点、参与人、提醒外的 extras），并用 `entry_uid` 指回那一行。

> 兼容例外：旧 `Calendar/` 笔记没有 `entry_uid`，也没有对应的行，继续以自身 frontmatter 为准只读渲染（见 §4.2 第 4 条）。

## 2. 参考实现调研结论

参考：`F:\我的资料库\T----同步盘\T----test\Obsidian-WiKi\.obsidian\plugins\xiaoyuanTasksCalendar`

### 2.1 周期笔记

- 设置里六类（fleeting / daily / weekly / monthly / quarterly / yearly），**每类三项**：`folder`、命名格式、`template`；另有"不存在则创建""创建后打开""每周起始日""默认打开的目标"等开关。
- 路径解析是纯函数：给定类型 + 参考日期 → 周期**锚点日** → 套格式 → `folder/name.md`。周依赖"每周起始日"，季按 `(月-1)/3` 取季首，年取 1 月 1 日。
- 模板由模板服务套用（装了 Templater 就用它，否则做简单的 `{{date}}`/`{{title}}` 替换）；**只在文件不存在时**套用，绝不覆盖已有文件。
- **没有聚合**：周报不汇总日记、月报不汇总周报，五类笔记是彼此独立的容器。插件只提供"打开某一期"的能力。

### 2.2 捕获

- 捕获是**配置驱动的模板插入**：一条配置 = 名称 + 目标（文件/文件夹下新建/某类周期笔记）+ 插入位置（顶部/底部/指定标题之后）+ 内容模板 + 变量 + 是否自动补 `➕`/`📅` + 是否打开文件。
- 运行时读目标文件 → 按插入位置算偏移 → 替换变量 → 写回；目标不存在时按模板创建。
- 变量来自选区、剪贴板、输入框与日期。
- **没有任何后台/隐式写盘**：每条配置都要用户显式触发（命令面板或头部按钮）。重复执行会重复插入，没有去重。

### 2.3 对我们的取舍

| 参考做法 | 我们的取舍 |
| --- | --- |
| 六类笔记 | 五类（去掉 fleeting，用户已定） |
| 每类三项配置 | 照搬，现有日记三项原样迁入 |
| 只建不改 | 照搬（幂等且不丢内容） |
| 捕获=手动模板插入 | 保留为"手动捕获"，另加事件创建时的自动落盘 |
| 无汇总 | 本轮不做自动汇总，改为只读的"周期窗口"（见 §5.5） |
| 无去重 | 自动写入必须带 uid 去重（见 §6.3） |

## 3. 字段归属表

"权威"列 = 冲突时以谁为准。所有"行"权威的字段都只存在行里，投影只读。

### 3.1 共用（笔记侧与事件侧都显示）

| 字段 | 笔记侧（token） | 事件侧（frontmatter 键） | 权威 | 备注 |
| --- | --- | --- | --- | --- |
| 标题/描述 | 描述文本 | 不写（join 得到） | 行 | D1=B：事件笔记不存副本 |
| 日期（自然日） | `📅 YYYY-MM-DD` | 不写；`dtstart` 只留时刻（见 3.2） | 行 | 轻量条目只有这一维，因此一律全日（D2） |
| 重复规则 | `🔁 every 2 weeks` | 不写 | 行 | `🏁 keep/delete` 是本应用扩展；旧笔记的 `rrule` 只读 |
| 提醒 | `⏰ -PT15M` | 不写 | 行 | P0 已把 `⏰` 提升为一等 token，规范位置紧跟 `📅`（D3） |
| 标签 | `#a #b`（可多个，保序） | 不写 | 行 | 事件侧靠 join 展示 |
| 状态 | `[ ] [x] [/] [-] [?]` | 不写 | 行 | **事件本身不引入完成态**（D5）：`x` 只在笔记侧表示完成，日历不因此改变外观 |
| 创建日期 | `➕` | 不写 | 行 | |
| 行前缀 | `-`/`*`/`1.` + 缩进 + `>` | — | 行 | |

### 3.2 事件专属

| 字段 | 落成 | 备注 |
| --- | --- | --- |
| 时刻 / 区间 | `start_time`、`end_time`、`all_day`、`tzid`（旧笔记仍读 `dtstart`/`dtend`） | 日期部分来自行，时刻来自这里；轻量条目没有时刻（D2） |
| 地点 | `location` | |
| 参与人 | `attendees`（待实现） | 本轮只解析不编辑 |
| 短备注 | `description` | 现有事件编辑器"备注"写这里 |
| 正文纪要 | 事件笔记正文 | 唯一整篇属于 extras 的内容 |
| 关联笔记 | `related_note` | |
| 例外实例 | `series_uid`、`recurrence_id`、`exdate` | 日历展开用 |
| 指针 | `entry_uid` | 指回创建日日记里的那一行 |
| 同步元数据 | `uid`、`source`、`remote_href`、`etag`、`sequence`、`dtstamp` | 永不写入行 |

### 3.3 任务专属

| 字段 | 笔记侧 | 事件侧 | 备注 |
| --- | --- | --- | --- |
| 优先级 | `🔺 ⏫ 🔼 🔽 ⏬` | 不写 | iCal `PRIORITY` 是 1–9，值域不同，不映射 |
| 依赖 | `🆔`、`⛔` | 不写 | `🆔` 同时充当自动写入的去重键 |
| 计划日期 | `⏳` | 不写 | 不影响日历落位（日历只按 `📅` 入桶） |
| 开始日期 | `🛫` | 不写 | 同上 |
| 完成日期 | `✅` | 不写 | 事件侧不展示完成态（D5） |
| 取消日期 | `❌` | 不写 | |

**任务专属字段为什么不写进事件 frontmatter**：D1=B 之后日历已经要按 `entry_uid` 去索引里取那一行，行上的字段直接可见，再抄一份到 frontmatter 只会制造第二份数据。代价是日历从"只读 frontmatter"变成"读索引 + join"，已在 P4 的计划里。

## 4. 存储与写入路径

### 4.1 两类存储

| | 轻量条目 | 重量条目 |
| --- | --- | --- |
| 行在哪 | 周期笔记（默认创建日日记） | **同一处**（创建日日记），不搬走 |
| 额外文件 | 无 | `Calendar/<日期>-<slug>-<uid8>.md` |
| 权威数据 | 那一行 | 那一行（事件笔记里没有第二份） |
| 事件笔记内容 | — | 事件专属 extras + `entry_uid: <uid>` 指针 |
| 日历来源 | `buildCalendarIndex` 的任务入桶（现有） | 任务入桶 + 按 `entry_uid` join 出 extras |
| 新增文件 | 否 | 是（仅此一次） |

事件笔记命名与写入沿用现有 `CalendarWorkspace.vue` 的 `Calendar/<YYYY-MM-DD>-<slug>-<uid8>.md` 规则；**旧笔记不迁移、不改写**。

### 4.2 唯一权威的保证

1. 两类条目：物理上都只有一行，共用字段无从重复。
2. 重量条目：**行仍是唯一权威**，事件笔记只是 extras 的容器。读写顺序固定为
   - 读：由事件笔记的 `entry_uid` 在索引里定位那一行；行的字段优先，extras 补齐事件专属字段。找不到行（旧笔记或行被删）→ 回退事件笔记自己的 frontmatter（legacy 通道）。
   - 写：只改行 → 事件笔记只更新 extras 与 `entry_uid`。共用字段（`summary`、日期部分、`rrule`、标签）**不写进事件笔记**，避免出现第二份。
3. 若事件笔记里残留了共用字段（旧版本或手改），它被视为"过期投影"：读取时忽略，下一次保存时删除。测试要求删一次后连续保存零 diff。
4. legacy 笔记（无 `entry_uid`）走只读通道：日历能显示、能打开，但任何字段编辑都要求先"升级"（建行 + 写指针），升级是显式动作，不在 `save` 里偷偷做。D7 已定**不加"未升级"徽标**。

### 4.3 原子性与一步撤销

- 磁盘写入：读全量 → 计算新全量 → 内容哈希比较 → 写；哈希在写入前变化则重读重算一次，仍冲突就报错，绝不覆盖。
- 同一路径写入串行化（进程内 `Map<path, Promise>` 队列），避免连续点击/重复触发交错。
- 编辑器内（CodeMirror）：行 + frontmatter 的改动合并为**一次 `dispatch`**（两个 `changes` 片段），保证一步撤销；禁止"先改行再单独写 frontmatter"。
- 事件笔记由日历侧保存时，同样只有一次 `write_file`。

### 4.4 与 `writeTaskLine` 的关系

```
菜单/编辑器/行命令
      │  构造 TaskLineModel
      ▼
 writeTaskLine(line, today, link)   ← 现有唯一出口，负责 token 规范化与状态↔日期联动
      │  规范行
      ▼
 writeEntry(target, line, extras)   ← 新增薄层
      │  ① 解析目标文件  ② 找插入/替换位置  ③ 幂等检查
      │  ④ 重量条目：重算 frontmatter  ⑤ 一次原子写
      ▼
周期笔记 / 事件笔记
```

- `writeEntry` **不重排 token**，也不再做联动；它只负责"落到哪、覆盖哪一行、要不要更新投影"。
- 反向同样成立：日历改标题 → 生成/替换行 → 走 `writeTaskLine` → 再重算投影。不存在绕过出口的第三条路径。
- `completeRecurringTaskLine` 生成新行的既有语义（新行插在旧行上方、旧行 `✅ 当天`）保持不变，只是外层换成 `writeEntry`。

## 5. 周期笔记

### 5.1 配置模型（新增，兼容现有）

```ts
type PeriodKind = 'daily' | 'weekly' | 'monthly' | 'quarterly' | 'yearly';

interface PeriodConfig {
  folder: string;    // 相对工作区，原样使用（不解析 token）
  format: string;    // 文件名格式，含扩展名，见 5.2
  template: string;  // 相对工作区的模板路径，空 = 内置默认
}

settings.periodic: Record<PeriodKind, PeriodConfig>;
```

- 迁移：现有 `dailyNotesFolder` / `dailyNotesFormat` / `dailyNotesTemplate` 在读取时映射为 `periodic.daily`，之后由 `periodic.daily` 作为权威；`setPeriodicConfig('daily', …)` 仍双写旧键，旧键保留一版（只读）。
- 默认值：日 `Daily/YYYY-MM-DD.md`、周 `Weekly/YYYY-[W]WW.md`、月 `Monthly/YYYY-MM.md`、季 `Quarterly/YYYY-[Q]Q.md`、年 `Yearly/YYYY.md`。`format` 含扩展名——沿用现有日记设置的老约定，迁移才能逐字照搬。
- `folder` 是**字面量**，不解析 token：否则默认文件夹 `Quarterly` 会被 `Q` 换成 `4uarterly`。日期差异放进 `format`。
- 新增两个通用项：`weekStartsOn`（默认 1=周一）、`captureHeading`（默认 `## 任务`）。

### 5.2 命名与锚点

| 类型 | 锚点日 | 可用 token |
| --- | --- | --- |
| 日 | 当天 | `YYYY` `MM` `DD` `ddd` `dddd` `WW` |
| 周 | 当周首日（依 `weekStartsOn`） | 同上 + `WW`（ISO 周） |
| 月 | 1 日 | `YYYY` `MM` |
| 季 | 季首月 1 日 | `YYYY` `Q` |
| 年 | 1 月 1 日 | `YYYY` |

- token 解析复用现有日记的格式化器，只新增 `WW`（两位数 ISO 周）与 `Q`；解析是单次左到右扫描，`[...]` 原样输出（如 `YYYY-[W]WW` 里的 `W`）。
- 周笔记的 `YYYY` 取**锚点日的日历年**：2026-01-01（周四）落在 2025-12-29 起始的那一周，因此名为 `2025-W01`；2026-12-28 起始的一周是 `2026-W53`。
- 路径解析是纯函数 `periodicPath(kind, date) → string`，单测覆盖跨年周、季首、闰年。

### 5.3 模板

- 纯文本变量替换，不引入模板引擎：`{{date}} {{time}} {{title}} {{yesterday}} {{tomorrow}} {{weekStart}} {{weekEnd}} {{monthStart}} {{monthEnd}} {{quarter}} {{year}} {{prev}} {{next}}`；并保留老日记模板的 `{{day}} {{week}} {{previous}}`，所以既有日记模板输出不变。
- 变量按周期锚点算：周笔记的 `{{date}}` 是周一，`{{weekStart}}`/`{{weekEnd}}` 是本期首尾，`{{prev}}`/`{{next}}` 是按各自 `format` 算出的 `[[上一期]]`/`[[下一期]]`。
- 只在文件不存在时套用；已有文件永不覆盖。
- 模板路径读不到 → 回退内置默认模板（日=内置日记模板，其余 `# {{title}}`）并提示，不阻断打开。

### 5.4 创建规则

- `openOrCreate(kind, date)`：解析路径 → 目录不存在则建 → 文件不存在则套模板写 → 返回路径并打开。
- 入口：命令面板的"打开今天 / 本周 / 本月 / 本季 / 本年"（`daily.open*` + `periodic.open*`）；侧栏"今天"沿用原入口。
- 不做定时批量预建（参考实现也没有）。

### 5.5 聚合

- **本轮不做自动汇总。** 参考实现没有，加汇总会带来"汇总行与被汇总行两份数据"的问题，与第 0 节第 1 条冲突。
- 替代方案：**周期窗口视图**。打开周报时，侧栏可按"本期范围内、未完成"过滤出日记里的行，只读、可跳转；不写入周报正文。月/季/年同理，窗口按各自锚点计算。
- 若将来确实需要"周报里固化一段汇总"，应作为**显式一次性的插入动作**（把当时的查询结果写成普通行/引用块），而不是持续同步。列为 D4。

### 5.6 "写创建当天日记"这条规则怎么落

- 目标解析与事件日期解耦：`targetPeriodicNote(entry)` 取 **`today`** 的 `daily`（D6 已定只允许"日"类型），与 `📅` 无关。
- 轻量与重量条目**都**走这条规则（D1=B）：行永远在创建当天的日记里，事件笔记只是 extras 容器。
- 插入位置：`captureHeading` 指定的标题之后；标题不存在时按设置"追加到文末"或"先建标题"，行为显式可见。
- 若今天是新的一天且日记不存在，先用 §5.4 的流程建（套模板），再写入行。
- `📅` 仍写事件日期（日历落位用），`➕` 写创建当天——两个日期各司其职，不互相泄漏。

## 6. 自动捕获

### 6.1 两层

| 层 | 触发 | 落点 | 去重 |
| --- | --- | --- | --- |
| 事件驱动（自动） | 从日历新建/保存条目 | 创建日周期笔记；重量条目写事件笔记 | 必带 uid，写前查重 |
| 捕获预设（手动） | 命令/按钮 | 配置指定 | 不去重（用户每按一次就是一条新行） |

参考实现的"捕获"只有第二层；第一层是本设计新增。

### 6.2 判定规则

| 动作 | 是否写盘 | 写哪里 |
| --- | --- | --- |
| 日历新建轻量条目 | 是 | 创建日日记的 `captureHeading` 下 |
| 日历新建重量条目 | 是 | 事件笔记正文首行（见 D1） |
| 在笔记里手写一行 | 否 | 就地 |
| 改日期 | 否 | 行不动，日历换天 |
| 勾选完成 / 改状态 | 否 | 行内（走现有 store） |
| 重复任务推进 | 是 | 同一文件、新行插旧行上方（现有语义） |
| 打开/滚动/刷新索引 | 否 | 只读 |

写盘只发生在"显式用户动作"里；渲染、索引刷新、无限滚动一律只读。这条是防重复写入的第一道闸。

### 6.3 幂等与去重

- 自动写入的行必带稳定 id：重量条目用 frontmatter `uid`，行里写 `🆔 <uid8>`；轻量条目同样生成 `🆔 <uid8>`。
- 写入前扫描目标文件里是否已有 `🆔 <uid8>`：
  - 有 → 原位替换该行（更新即幂等）。
  - 无 → 在 `captureHeading` 下插入。
- 同一目标文件重复运行任意次，结果与运行一次相同（单测：连续 3 次 `writeEntry` 后文件行数不变）。
- 用户手写的行不带 `🆔`，永远不会被自动写入覆盖。

### 6.4 并发与冲突

- 进程内按路径串行；连续点击、重复触发、两个视图同时保存 → 排队。
- 每次写前重读文件并比对哈希；不一致 → 重算一次；再不一致 → 报冲突并保留用户当前编辑，不覆盖。
- 无限滚动/日历翻页只改变读取窗口，不进入写队列。

## 7. 与 Obsidian 的兼容边界

### 7.1 原生格式（可被其他插件正确读取）

- 任务行语法与全部 token（`📅 ⏰ ⏳ 🛫 ➕ ✅ ❌ 🔁 🔺⏫🔼🔽⏬ 🆔 ⛔`）——除 `⏰` 外均为 Obsidian Tasks 原生；`⏰` 是本应用扩展的行内 token（见 7.2）。
- `#tag` 行内多个标签、`categories` 属性。
- frontmatter 的 iCal 形状键（`summary`、`dtstart`、`dtend`、`rrule`、`location`、`alarms`、`status`、`uid`）——本应用既有约定，外部日历工具也认。

### 7.2 靠忽略策略

| 项 | 策略 |
| --- | --- |
| `⏰ -PT15M` | Tasks 不识别，作为行内普通文本存活；本应用解析为提醒 |
| `created` / `completed` / `cancelled` / `priority` / `id` / `blocked_by` | 自有键；Obsidian Tasks 只读行内 token，不会误读，也不会改写 |
| `series_uid` / `recurrence_id` / `exdate` | 仅本应用使用 |
| `🏁 keep/delete` | 只存在于行内，事件侧丢弃 |
| 无法解析的 rrule 片段 | 只读保留，原样写回，不尝试用自然语言重写 |

### 7.3 只读保护

- legacy 事件笔记（frontmatter 有值、正文无任务行）：日历可显示、可打开；字段编辑要求显式升级。
- 参与人：本轮只解析不编辑。
- 绝不在 frontmatter 与行之间做"双向自由同步"——只有"行 → 投影"一个方向（legacy 例外，且只读）。
